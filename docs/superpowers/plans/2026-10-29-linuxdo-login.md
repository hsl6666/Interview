# LINUX DO Connect 登录接入

## 行为与边界

- 增加 `/login`，使用 LINUX DO OAuth2 授权码登录；后端完成 code 换 token 和资料读取。
- 用户已确认全站需要登录：除登录相关接口及健康检查外，业务页面和接口均要求会话。普通用户可参加自己的面试，后台及全量结果仅管理员可访问。
- 管理员由 `LINUXDO_ADMIN_IDS` 明确指定；空白名单时普通账号仍可参加面试，但无人拥有后台权限；不采用首位登录者自动成为管理员。
- 随机不透明会话通过 HttpOnly/SameSite=Lax Cookie 保存，数据库只存令牌哈希，固定有效期；退出服务端撤销。
- OAuth state 绑定浏览器、10 分钟有效且单次消费；回跳路径限定站内面试/后台/结果页面和后端手机上传页，拒绝开放重定向。
- 所有业务写操作校验 Origin；生产使用 Secure Cookie 和 HTTPS，CORS 限定配置的前端。
- 未配置 OAuth 应用时所有业务页面和接口仍受保护，登录页显示未就绪提示。

## 实施顺序与验证

1. 通过 API 集成测试定义未登录拦截，补认证模型及依赖。
2. 测试并实现授权发起、state 验证、回调、白名单、会话与退出；仅模拟外部 OAuth HTTP 和时钟。
3. 实现登录界面、前端路由守卫、登录过期回跳、管理后台用户与退出菜单。
4. 补充开发/部署环境变量示例与文档，运行后端回归、前端构建和浏览器验收。
5. 使用用户提供的应用凭证完成真实授权联调；缺少凭证时明确标记验证边界。

## 外部配置

用户选择新建独立的“AI 面试平台”应用，先本机调通；已有“友链登录”应用保持原样。凭证仅保存到已忽略的 `backend/.env`。本地回调为 `http://127.0.0.1:8011/api/auth/linuxdo/callback`，前端为 `http://127.0.0.1:5175`。

- 新面试在创建事务中绑定登录用户；任何账号均不能认领已有无归属面试。历史面试仅管理员可见。附件和快照经过认证与归属校验，不再裸露静态目录。
