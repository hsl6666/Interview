# 口试套题改造

## 已确认行为

- 口试题管理以套题为第一层：先建 A 套，再进入套内新增、编辑、删除和排序题目。
- 自定义组套可跨多套选题、预览、调整顺序。用户已确认复制为独立题目，修改和删除互不影响。
- 管理员启用一整套供后续口试使用；按套内顺序出题，岗位标签保留为检索信息。
- 旧题目归入默认套题；现有发布状态和排序保留。已开始的口试固定题目快照。
- 新套题默认草稿；空套、没有已发布题目的套不能启用。当前使用套题不能删除、下架或移除最后一道已发布题，需先切换。

## 实施方案

1. `backend/app/models.py` 增加套题、当前选择与口试快照；口试题增加所属套题。`db.py` 调用幂等 SQLite 迁移，迁移前备份现有数据库。
2. 新增 `services/oral_question_sets.py`、`api/oral_question_sets.py`，处理套题 CRUD、跨套复制、发布/启用、会话快照；保留旧题目接口并验证归属和活跃套题约束。
3. 管理页提取独立 `OralQuestionSetsManager`，提供套题列表、套内管理、组合套题弹窗（来源筛选、跨页选择、已选顺序预览）。更新 TS 类型和 API。
4. 候选人口试加载会话快照，不再静默回退到写死的题目。加载失败/无可用套题时显示明确状态并禁止录音、提交。

## 验证

- 使用临时 SQLite 数据库、FastAPI TestClient 和 unittest，通过真实 API 按红—绿循环验证：套题归属、复制隔离与顺序、非法 ID/重复选择、发布/启用、删除保护、已开始会话固定题目。
- 使用旧表结构夹具验证迁移保留原题、只执行一次、删除后不复活。
- 执行前端 TypeScript/Vite 构建。
- 浏览器验证新建套题 → 新建题目 → 跨套勾选 → 调序 → 保存新套，并验证桌面和窄屏布局。
- 重启本地服务，在指定管理页面交付。不提交或发布远程代码。
